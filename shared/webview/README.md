# Shared webview assets

JavaScript and CSS used by both shells' WebKit views: browser automation (step 2.9) and preview styling (step 1.9).

## Preview tiles (F9)

The core embeds these files (`include_str!` in `core/crates/preview`) and sends every preview as one self-contained HTML document in `preview.updated` events and `preview.get` replies. Shells don't load the files themselves.

- `preview.html`: the page skeleton. Its content security policy allows only inline styles, our inline script, and images and media the document references (`file:`, `data:`, plus remote images).
- `preview.css`: typography, light and dark colours, code blocks, the line-number gutter, notices. Syntax colours (`syn-*` classes) are generated by the core from two syntect themes and appended.
- `preview.js`: `azulejoPreview.swap(html)`. When an update arrives for the file a tile already shows, the shell calls it with the event's `html` instead of reloading, so the reader keeps their scroll position (or stays at the bottom of a growing file). It returns `false` when the page isn't one of ours; load the document from scratch then.

Native kinds (`image`, `video`, `audio`, `pdf`) carry no HTML: shells show `path` with QuickLook on macOS and GTK on Linux. Links in markdown that point to local files arrive as `file://` URLs; load the page with read access to the file's folder (WKWebView `loadHTMLString(_:baseURL:)` with a `file://` base, or `loadFileURL(_:allowingReadAccessTo:)`) so images resolve.
