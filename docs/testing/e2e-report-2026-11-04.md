## Environment limits

- **The screen was locked again for the whole run** (`CGSSessionScreenIsLocked = 1`, checked with `CGSessionCopyCurrentDictionary` at the start). So the display link never ticked, `screencapture -l` failed, and cold start's first frame fell back to its 2 s timer. Every capture is the app's own render (`shot`, or `capture`'s `-app.png`). Those can't see Quick Look views, WebKit pages in a background window, or (it seems) a terminal that's moving mid-swap. `e2e/stale-check.sh` refuses to run with the screen locked; I ran it once with `STALE_CHECK_FORCE=1` to get its lock-mode data, and its screen-on checks fail as designed.
- **Within the ground rules throughout.** No OS input, no window raised, dev instances only (`e2e-*`, herdr sessions `azj-dev-e2e-*`), no real SSH (machines and mockup use the stand-in), no clipboard, keychain or `~/Downloads`, no `herdr update`. N1b stops and starts the dev session's herdr only, through `e2e/hd` (which refuses anything not named `azj-dev-e2e*`). One instance at a time.
- **Ghostty:** the worktree's empty `vendor/ghostty` was symlinked to the main checkout's built copy for the build, then put back as an empty folder. Not committed.
- **Evidence lost to resets:** the A9 scripts keep their captures under `.dev/<name>/out`, which `dev.sh --reset` wipes; for browser, preview, files, restore and headers only the logs remain (`A9-*.log`).

## Failures

### F5 (N1c, minor): ⌘K over an open find bar hands the keyboard to the PTY
**Repro:** in a terminal, ⌘F, type a query, ⌘K, Esc.
**Expected:** the keyboard goes back to the find bar.
**Actual:** the bar stays open with its query, but the first responder is the terminal surface (`responder terminal`), so the next keys go to the shell, Enter included. 4 of 4 runs. A tab switch and back (N1d) does the same.
**Cause (read, not changed):** `palette.onClose` (`PaletteActions.swift:79`) calls the tile's `setFocused(true)`. `TerminalTileView.setFocused` keeps the bar only when `finder.bar.holdsKeyboard`, which checks that the bar's field editor is first responder. At that moment the palette's field is, so the surface takes the keyboard. `PreviewTileView` has the same guard. The bar needs to remember it had the keyboard, or the palette needs to restore the previous first responder.
**Evidence:** `.dev/e2e.out/N-fixes/fixes/automation.log` line 73.

### F6 (N5c, minor): the agent badge leaves the header strip mid-motion
**Repro:** 4 terminals in Tile, a badge on the master (`herdr pane report-agent … --state working`), `anim duration 1500`, `alt+shift+l`, capture at 650 ms.
**Expected:** the badge rides in the header strip's right end, like the title (D.5, V8).
**Actual:** the header strip follows the crop clip (bf9f340) but the badge doesn't: it sits ~26 pt below the strip and past the moving card's right edge. Reproduced in both N runs. Where the two fixes meet: the badge moved into the header (19a1b17) and the header learned to ride the clip (bf9f340) on separate branches.
**Evidence:** `e2e-v2/n5-badge-detached-mid-swap.png` (local capture).

### V19 (N1h, minor): the find bar doesn't fit narrow tiles
**Repro:** ⌘F in a terminal, then `window-size 480 320` (or a browser tile under ~150 pt).
**Expected:** like the headers since V6: controls drop out whole below a minimum width.
**Actual:** the query, "No matches", the magnifier and the chevrons draw over each other ("toNes").
**Evidence:** `e2e-v2/n1h-find-bar-min-size-overlap.png` (local capture).

### N4c (V6 regressed, minor): no tab visible at the minimum window size
**Repro:** any session, `window-size 480 320`.
**Expected:** at least the selected tab (11-03 showed it as an icon).
**Actual:** the strip shrinks to the "+" button; no tab, selected or not. Since the overflow change, tabs stop at `tabFitMinWidth` and the strip scrolls, but at this width the strip has no room for even one.
**Evidence:** `e2e-v2/v6-min-size-no-tabs.png` (local capture) (polish.sh's own after-image `e2e-v1/fix-min-size.png` shows the same), `e2e-v2/n4-overflow-min-banner.png` (local capture).
